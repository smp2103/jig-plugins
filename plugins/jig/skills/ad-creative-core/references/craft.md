# 전문 편집 기법 — "배치"를 "편집"으로 올리는 규율

레이어를 놓는 것과 연출하는 것은 다르다. 아래는 **도구로 실제 표현 가능한 것만** 정리한 실행 규칙 (2026-07-29 렌더 검증).

## 1. 스태거 — 가장 크게 티나는 한 가지

레이어가 **동시에 튀어나오면** 아무리 색이 좋아도 싸구려로 보인다. 프로는 읽는 순서대로 시차를 준다.

`motion.enter.delayMs`로 구현 (2026-07-29 추가, enter 전용).

```
delayMs = 화면 내 등장순서 × 90ms      (0 / 90 / 180 / 270 / 360)
5단계 넘어가면 90ms 고정 — 너무 길어지면 늘어진다
```

순서는 **시선 순서**: 배경패널 → 칩/뱃지 → 헤드라인 1행 → 2행 → 언더라인 → 서브 → CTA.
같은 씬의 형제 요소(3중 틱 라벨 등)는 60~80ms로 촘촘하게.

**주의**: delayMs는 레이어 `start_ms` 기준 상대값이다. start_ms를 어긋나게 잡고 delay까지 주면 이중 지연이 된다 — 씬 요소는 start_ms를 씬 시작에 통일하고 **시차는 delayMs로만** 만든다.

## 2. 마스크 리빌 (wipe) — 프리미엄 등장의 절반

`wipeRight | wipeLeft | wipeUp | wipeDown` (2026-07-29 추가). clip-path가 쓸고 지나가며 드러나고 **opacity는 건드리지 않는다** — fade보다 훨씬 고급스럽다.

- **헤드라인**: `wipeRight` 500~650ms + easeOut. 좌→우로 읽는 방향과 일치
- **언더라인/구분선**: `wipeRight` 400~500ms — 선이 그어지는 연출 (slideRight보다 정확)
- **밴드/패널**: `wipeDown`(상단 밴드) / `wipeUp`(하단 밴드) 350~450ms — 패널이 내려오며 자리를 만든다
- **퇴장**에도 지정 가능 — 등장 wipe와 반대 방향을 주면 "쓸려 나가는" 마무리
- charAnimation과 조합 금지 (두 마스크가 겹쳐 지저분해짐). 리빌은 wipe, 글자단위는 charAnimation — **택일**

## 3. 켄번스 — 정적 클립을 살리는 슬로우 줌

> **⚠️ 소재에 이미 카메라 무빙이 있으면 켄번스를 걸지 않는다 (2026-08-04 실측).**
> 두 움직임이 미세하게 어긋나 화면이 떨리고, 보는 사람에겐 "왜 갑자기 커지지?" 로 읽힌다.
> 프리즈+펀치는 더 심하다 — 정지가 티가 안 나고 확대만 눈에 띈다.
> **생성 프롬프트를 우리가 썼다면 무빙 여부를 알고 있다.** "slow push-in", "camera drifts",
> "dolly" 같은 지시를 넣었으면 켄번스·프리즈를 **빼는 게 기본**이다.
> 업로드 소재면 `analyze_video` 로 컷을 나눈 뒤 **첫/끝 프레임을 비교**해 무빙을 확인할 것.

`set_clip_framing`의 `end_scale` / `end_offset_x` / `end_offset_y` (2026-07-29 추가). 클립 표시 구간 동안 시작값 → 종료값으로 보간된다. **영상만 움직이고 텍스트 레이어는 고정**된다.

우리 파이프라인에서 특히 중요하다: Kling에 일부러 "nearly static"을 주문하기 때문에 **클립 자체가 정적**이다. 여기에 슬로우 줌을 얹어야 "영상"이 된다.

```
푸시인(집중): scale 1.0 → end_scale 1.08~1.12
풀아웃(개방): scale 1.10 → end_scale 1.0
```

**켄번스 전에 "기본 크롭"부터 정한다.** 생성 클립은 피사체가 화면 한쪽에 몰리고 나머지가 빈 배경인 경우가 흔하다. 이 상태에 8~12% 줌만 얹으면 **빈 배경이 그대로 살아 있는 채로 움직일 뿐**이다.

- `get_frame_regions(video_id=…)` 의 ascii 에서 `..` 밴드가 소스의 절반 이상이면 → `scale` 을 1.8~2.1 까지 올려 그 밴드를 잘라낸다
- 자른 뒤 `offset_y` 로 위아래 균형을 맞춘다 — 위를 자르면 아래가 남는다
- 기본 크롭을 정한 **다음에** 그 위에 켄번스를 얹는다 (`scale 2.05 → end_scale 2.15` 처럼 조인 값 기준으로)

- **5초 클립 기준 8~12%가 적정**. 15% 넘으면 줌이 눈에 띄어 촌스럽고, 5% 미만은 안 한 것과 같다
- **scale은 절대 1.0 미만 금지** — 화면에 검은 여백이 생긴다. 풀아웃은 "높은 값에서 1.0으로" 내려오는 것
- **씬마다 방향을 교대**하면 리듬이 생긴다 (푸시인 → 풀아웃 → 푸시인…). 전 씬 같은 방향은 단조롭다
- **감정 매칭**: 문제 제기·강조 씬은 푸시인(조여드는 느낌), 해결·개방 씬은 풀아웃
- **제품 클로즈업/패키지샷은 정적이거나 아주 미세하게(1.0→1.06)** — 제품은 안정적으로 보여야 신뢰가 간다
- `end_offset_x/y`로 팬(pan)도 가능. 단 오프셋을 쓰려면 scale 여유가 필요하다(cover 규칙과 동일)
- **피사체를 밀어 텍스트존을 만들 때**: `offset_x` **양수 = 피사체가 오른쪽으로**. 실측에서 부호를 반대로 잡아 세 번 재시도한 적이 있다. 밀기 전에 `get_frame_regions` 로 현재 `subject_bbox` 를 재고, 민 뒤에 다시 재서 확인할 것 — 이동량은 `offset × scale` 이라 감으로 맞히기 어렵다
- easing은 `linear` 기본이 정답 — 등속 드리프트가 가장 자연스럽다. `easeInOut`은 짧은 강조 줌에만
- **커버 크롭과 겸용**: 세로 클립을 1:1에 넣어 scale 1.85로 커버 중이면, 켄번스는 `1.85 → 1.95`처럼 그 위에서 얹는다

### 저더(judder) — 켄번스보다 먼저 확인할 것

**Kling·Veo 생성물은 전부 24fps**다. 타임라인이 30fps면 4프레임마다 1장이 복제되어(실측 16%) 불균등 케이던스 = "화면이 지진난 것처럼" 끊긴다. 켄번스처럼 지속 모션을 얹으면 더 도드라진다.

타임라인 fps 는 소스에서 정해진다(전부 같으면 그 값, 섞이면 최댓값). 한 소재 안에서는 같은 provider·fps 의 클립을 쓰는 게 안전하다.
- **에디터 프리뷰의 끊김은 이것과 무관**할 수 있다. 프리뷰는 브라우저 실시간 재생이라 원래 프레임을 떨어뜨린다. 판정은 반드시 **렌더 결과물**로 한다

## 4. 이징·듀레이션 규율

| 항목 | 규칙 |
|---|---|
| 등장 | **easeOut 고정** (빠르게 들어와 부드럽게 안착) |
| 퇴장 | **easeIn** |
| linear | 티커 외 금지 |
| spring | **화면당 1개만** — 뱃지·빅넘버 같은 포인트 요소에만 |

| 듀레이션 대역 | 값 | 대상 |
|---|---|---|
| 마이크로 | 180~250ms | 칩·뱃지·틱 |
| 표준 | 320~450ms | 텍스트·밴드·카드 |
| 히어로 | 500~650ms | 빅넘버·헤드라인 리빌 |

**800ms 초과 금지** — 숏폼에서는 무조건 느리게 읽힌다.

## 5. 타이포 위계 — 크기가 아니라 비율

단계별로 **1.5~1.7배**를 지켜야 "위계"로 읽힌다. 애매한 1.2배 차이는 위계가 아니라 그냥 실수처럼 보인다.

한 소재에서 쓸 렌더 px를 3~4단으로 **먼저 고정**하고 그 안에서만 고른다:
```
9:16 예: 42 / 68 / 110 / 180   (각 ≈1.6배)
16:9 예: 48 / 80 / 130 / 210
```

**숫자는 별도 시스템**이다. "1,500mg"은 문장이 아니라 데이터다:
- 본문보다 **1.4~1.6배** 크게
- `letterSpacing: -2 ~ -4` (숫자는 자간을 좁혀야 덩어리로 읽힌다)
- 포인트 컬러 + 단위(mg/원/%)는 한 단계 작게 → 숫자 자체가 그래픽이 된다

## 6. 배킹 처리 — 사각형을 안 보이게

`backgroundOpacity 0.5` 검정 박스는 경계가 그대로 보여서 제일 아마추어처럼 보인다.

- **그라디언트 스크림**: 세로 그라디언트(`angleDeg:180` = `offset 0` 이 화면 위). **텍스트가 있는 쪽을 어둡게** — 상단 카피면 `0.88 → 0.62 → 0`, 하단 카피면 `0 → 0.30 → 0.86`. 중간 stop 없이 2단으로 하면 꺾이는 지점이 보인다. 도형 높이는 피사체가 시작되기 전에 끝내 제품에 안 닿게 한다. 경계 없이 대비 확보. **적용 지점 3곳 전부 지원됨 (2026-07-30 추가)** — 자막(`set_subtitle_style.backgroundGradient`), 도형 패널(`add/update_shape_layer` 의 `shape.backgroundGradient`), 텍스트 배킹 박스(`update_text_layer.patch.backingGradient`). `get_frame_palette` 의 `suggested.scrim` 을 그대로 붙여넣으면 된다.
  - 주의: 같은 호출에 단색(`backgroundColor`/`backingColor`)을 함께 보내면 **단색이 이기고 그라디언트가 지워진다**. 스크림으로 바꿀 때는 그라디언트만 보낼 것.
- **pill 배킹**: 칩·뱃지는 `backingRadius 40`으로 완전 라운드. 단, backing은 **레이어 박스 폭을 따라가므로** 텍스트 폭에 맞춰 박스를 좁혀야 함 (안 그러면 길쭉한 알약)
- **불투명 패널**: 정보 밀도가 높은 존에만. 반투명(0.78~0.88)이 풀불투명보다 영상과 붙는다
- **깊이는 사각형을 더 쌓아서 만들지 않는다** (2026-07-30): 라디얼 글로우 오브(`backgroundRadialGradient`) / 네온·그림자(`effects.shadowColor`+`shadowBlur`) / 글래스(`effects.backdropBlur` + opacity 0.15~0.35). 레시피는 `ad-brand` 스킬 `references/genre-recipes.md` §2-1

**그림자는 광원 하나**: 모든 레이어의 `shadowOffsetY`는 같은 부호·같은 값(예: +2). 블러만 고도에 비례 — 패널 위 텍스트 6~10, 영상 위에 떠 있는 요소 18~26. 방향이 제각각이면 깊이감이 아니라 지저분함이 된다.

## 7. 세이프 에어리어 — 플랫폼 UI에 가려지는 영역

캔버스를 그냥 1080×1920으로 보면 실제 피드에서 잘린다.

| 지면 | 피해야 할 영역 |
|---|---|
| 틱톡 | 우측 **12%**(버튼 레일), 하단 **18%**(캡션·계정명) |
| 릴스/쇼츠 | 하단 **20%**, 우측 10% |
| 공통 안전 | 상단 8% (상태바·헤더) |

- CTA·핵심 카피·로고는 **y 0.08~0.78** 안에 둔다
- 자막 `marginV`는 이 하단 영역을 피해서 잡는다 (9:16에서 marginV 140~260)
- 우측 세로 UI 때문에 **9:16의 텍스트는 살짝 좌측 정렬**이 안전하다

## 8. 타임라인 리듬 — 등장만 있고 퇴장이 없으면 배너다

모든 레이어가 `start_ms 0 ~ end_ms 끝`이면 영상이 아니라 정지 이미지에 영상을 덧댄 것이다.

- 훅 문구는 훅 구간에만, 근거는 근거 씬에만, CTA는 마지막 구간에만
- **씬 경계에서 레이어를 교체**한다 (compact_clip_timeline 응답의 timeline이 경계표)
- 상시 노출은 브랜드 pill·AI 주석 정도로 제한
- 예외: 광고주가 "상단 고정 문구"를 요구한 경우 (리턴큐형) — 이땐 고정이 정답

## 9. QA 샘플링 규칙

임의 시점을 찍지 말고 **두 종류를 반드시 포함**:
1. **씬 경계 + 200ms** — 그 씬의 레이어가 다 들어온 직후(스태거 완료 시점)
2. **씬 중앙** — 모션이 끝난 정적 상태에서 레이아웃 검사

`preview_edit_frame`의 `at_ms_list`에 두 세트를 한 번에 넣는다. 모션 자체를 검증하려면 **한 애니메이션 구간을 3등분해 찍어** 마스크/시차가 실제로 진행되는지 본다 (예: delay+80 / +250 / +450).

## 10. 편집자 기술 — 클립 자체를 만진다

레이어만 얹는 건 "그림판 위 자막"이다. 프리미어/AE 편집자가 실제로 하는 건 **소스 클립을 손보는 것**이고,
이게 초보 편집과 프로 편집을 가르는 지점이다. 전부 `set_clip_framing` 한 번에 들어간다.

### 10-1. 컬러 그레이딩 (`grade`) — 제일 먼저 하는 일

컷마다 **의도한 색이 달라야** 시간 경과·전후 대비가 읽힌다. 전 컷을 같은 색으로 두면 편집을 안 한 것이다.

| 목적 | 값 |
|---|---|
| Before / 날것 / 과거 | `saturate 0.7`, `contrast 0.9`, `temperature -8` (차갑고 빠진 색) |
| After / 완성 / 현재 | `saturate 1.15`, `contrast 1.1`, `temperature 12~16` (따뜻하고 진한 색) |
| 필름 룩 | 위 + `vignette 0.35~0.45`, `grain 0.15~0.25` |
| 하이엔드 뷰티/제품 | `bloom 6~10` (하이라이트 번짐) |

- **비네트는 0.4 이하로.** 0.9 는 명백히 인공적이다.
- **그레인은 0.25 이하.** 결정론적 노이즈라 프레임마다 흔들리진 않지만, 넘기면 화질 저하로만 읽힌다.
- `temperature` 는 양수=따뜻(세피아), 음수=차갑(휴 로테이트). ±20 넘기면 색이 무너진다.

### 10-2. 컷 전환 (`transition`) — 하드컷만 쓰면 아마추어 티가 난다

클립 **시작**에 얹힌다. 전 컷에 거는 게 아니다.

- `flash` (120~220ms): 비트 전환. 전/후 대비를 때릴 때. 남용하면 싸구려.
- `dissolve` (300~600ms): 시간 경과·회상.
- `whip` (150~250ms) + `direction`: 앞뒤 클립에 실제 팬 움직임이 있을 때만. 정지 화면에 걸면 어색하다.

**한 영상에 전환은 1~2개.** 전 컷에 걸면 전환이 내용이 되어버린다.

### 10-3. 속도 (`speed`)

`0.6~0.8` = 히어로 비트의 슬로모. `1.4~2.0` = 지루한 이동 구간 압축.
슬로모는 **오디오가 없을 때만** 자연스럽다 (BGM 위라면 무방).

### 10-4. 프리즈 프레임 + 펀치 (`freeze`) — "여기가 히어로 샷이다"

```
freeze: { at_ms: 2600, hold_ms: 700, punch: 1.12 }
```

- `at_ms` 는 **클립 로컬 기준**(타임라인 절대시각이 아니다). 4초 클립의 2600 = 그 클립 2.6초 지점.
- 정지 동안 화면이 **완전히 멈춘다**(검증: 같은 홀드 구간 두 프레임의 md5 동일).
- 정지가 끝나면 멈춰 있던 만큼 되돌려 이어 재생한다 — 클립 뒷부분이 잘리지 않는다.
- `punch` 1.08~1.15. 홀드 앞 1/3 구간에 걸쳐 밀고 들어간다.
- **`punch_release` (기본 0.8 = 홀드 길이의 80%)** — 정지가 끝난 뒤 줌이 풀리는 시간.
  0 으로 두면 해제 순간 화면이 **툭 튄다**(실측: 확대됐다 확 풀리는 게 그대로 보인다).
  0.6~1.2 가 자연스럽다.
- **홀드 시점에 텍스트를 같이 띄운다.** 프리즈만 하면 "영상이 멈췄네"로 읽힌다.
- `hold_ms` 는 500~900. 1초 넘기면 버퍼링처럼 보인다.


### 10-5. 레이어 지속 모션 (`drift`) — 정지한 레이어는 템플릿 티가 난다

enter/exit 와 **별개로** 표시 구간 내내 이어진다. 들어와서 완전히 멈춰 있는 레이어가
"에이전트가 찍어낸 자막" 느낌의 가장 큰 원인이다.

```
drift: { end_scale: 1.03, end_x: 14, easing: "easeInOut" }
```

- `end_scale` **1.02~1.04**. 1.06 이상은 눈에 띄게 커져서 산만하다.
- `end_x` / `end_y` 는 **디자인 px**(비율 아님). 표시 구간 전체에 걸쳐 선형 이동한다.
- **세이프에어리어를 먹는다.** y 0.10 에 있는 레이어에 `end_y -24` 를 걸면 상단이 잘린다(측정으로 확인).
  드리프트 값을 더한 최종 위치가 세이프에어리어 안인지 계산할 것.
- **배분 규칙**: 배경·장식 레이어에 드리프트, 제품명·CTA 는 정지. 전부 움직이면 읽히지 않는다.

### 10-6. 텍스트 트랙 매트 (`text_fill`) — 글자 안에 영상이 비친다

AE 클래식. `preview_video_frame` 으로 클립 스틸을 뽑아 그 URL 을 넣는다.

- **폰트 웨이트 800+ / 대형 글자에서만 성립.** 얇은 글자는 이미지가 들어갈 면적이 없다.
- **채우는 이미지가 배경과 대비돼야 읽힌다.** 같은 클립의 스틸을 그 클립 위에 채우면
  글자와 배경이 같은 그림이라 사실상 안 보인다(실측으로 확인 — 최악의 조합).
  → 채울 이미지는 **다른 컷**에서, 되도록 명도가 반대인 것으로 고른다.
- `font_gradient` 와 같은 경로를 쓰며 트랙 매트가 이긴다. 둘 다 넣지 말 것.
- 지울 땐 `update_layer_box` 에 `text_fill: null`. (`drift` 도 동일하게 `null` 로 제거)

### 10-7. 모션 블러 (`motion.motion_blur`) — 슬라이드가 "CSS 트랜지션"으로 안 보이게

enter/exit **진행 중에만** 걸리고 레이어가 멈추면 0 이 된다. 최종 화면은 선명하다(실측 확인).

- 텍스트 **3~6px**, 대형 그래픽 6~10px.
- **빠른 모션에서만 의미 있다** — `durationMs <= 450`. 느린 페이드에 걸면 보이지도 않고 GPU 레이어만 늘어난다.
- slideUp/slideLeft 같은 **이동 계열**과 짝지을 것. `fade` 에 걸면 흐릿하게 나타났다 선명해지는 이상한 효과가 된다.
- 씬의 모든 레이어에 걸지 말 것. **가장 크게 움직이는 1~2개**만.

### 10-8. 2.5D 퍼스펙티브 (`perspective`) — 사각형을 공간에 놓는다

평면 레이어를 원근 공간에 눕힌다. **패널/카드가 "화면에 붙은 사각형"이 아니라 "장면 안의 물체"로 읽힌다.**

```
perspective: { distance: 1100, rotate_y: 13, settle: true }
```

- `rotate_y` **8~14도**가 스윗스팟. 20도를 넘으면 글자를 못 읽는다.
- `distance` 800~2000. 작을수록 왜곡이 강하다.
- `settle: true` — 기울어진 채 등장해 **표시 구간 앞 40%** 에 걸쳐 정면으로 선다.
  정적인 패널을 "연출된 것"으로 만드는 가장 값싼 방법.
- **한 소재에 하나.** 여러 레이어를 동시에 눕히면 화면이 기울어 보이는 착시가 생긴다.
- `drift` 와 함께 걸 수 있다(원근이 먼저, 드리프트가 뒤에 곱해진다).

### 10-9. 라이트 리크 (`light_leak`) — 필름 룩의 마지막 한 겹

렌즈로 새어 든 빛의 띠가 화면을 가로질러 스윕한다. screen 블렌드라 **밝은 부분만** 물든다.

```
light_leak: { color: "#ffb066", intensity: 0.36, angle_deg: 28, sweeps: 1 }
```

- `intensity` **0.25~0.45**. 0.5를 넘으면 효과가 아니라 버그로 보인다.
- `sweeps` 는 클립 구간 동안 화면을 지나가는 횟수. 보통 1. 2 이상은 산만하다.
- **한 클립에만.** 감정 정점이나 CTA 직전 마지막 비트가 정석이다.
- `grade.vignette` 와 같이 쓰면 필름 룩이 완성되지만, 둘 다 세게 걸면 화질 문제처럼 보인다.

### 10-10. 조합 — 이 순서로 쌓는다

1. `grade` 로 컷마다 색을 가른다 (전 컷 필수)
2. 히어로 컷 하나에 `freeze` + `punch`, 그 프레임에 텍스트를 맞춘다
3. 컷 경계 1~2곳에 `transition`
4. 장식 레이어에 `drift`, 핵심 카피는 정지 / 가장 크게 움직이는 레이어에 `motion_blur`
5. 대비가 확보되는 한 곳에만 `text_fill`
6. 히어로 패널 하나에 `perspective`(settle), 마지막 비트 클립 하나에 `light_leak`

**전부 다 쓰면 그것도 실패다.** 한 영상에 4~5개 컷이면 위에서 3가지 정도만 쓴다.

## 11. 아직 도구로 안 되는 것 (요청 시 개발 필요)

- 레이어 그룹 단위 변형(그룹 통째로 회전/스케일)
- 임의 다각형 마스크·모션 트래킹(피사체를 따라다니는 레이어)
- 키프레임 커스텀 경로(모션 패스), 3D 카메라 이동

이 중 하나가 필요한 연출이면 **그 연출을 우회하지 말고 사용자에게 도구 추가를 제안**할 것.
