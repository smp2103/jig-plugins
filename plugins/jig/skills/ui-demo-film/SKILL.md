# 제품 UI 모션 광고 (SaaS 데모 필름)

> 이 장르가 멋져 보이는 이유는 에셋이 아니라 **화면 전체가 카메라 한 대로 이어져 움직이기 때문**이다.
> 장면을 지우고 새 장면을 띄우면 슬라이드쇼다. 어두운 배경에 글로우를 얹으면 "AI 가 만든 대시보드"다.
> 이 문서는 실제 반려 세 번(① 흰 박스+글자 한 줄 = "그림판 같다" ② 회색 막대·색 점 = "AI 도형 같다" ③ 어두운 HUD+캡슐 = 채팅 제작본)에서 나왔다.

광고 요청이 **앱·서비스의 사용 장면**을 보여 주는 것이면 `ad-brand` 의 장르(특히 HUD테크)가 아니라 이 스킬이다. 모션 수치는 `motion-craft`, 도구 기본기는 `ad-creative-core`.

## 0. 하지 않는 것 (먼저 읽는다)

- **어두운 배경 + 도트 그리드 + 글로우 + 네온 테두리.** 밝은 종이색 단색이 기본이다.
- **장면 사이 플래시·화이트아웃 전환.** 전환은 카메라가 한다(§3-1).
- **캡슐 라벨**(완전 라운드 + 단색 채움)과 **도형+텍스트 2장**으로 만든 버튼·칩. 판 위 글자는 frame + 자식 text.
- **자리표시자**: 회색 글줄 막대, 색 점, 빈 타일. 실제 아이콘·실제 글자·실제 썸네일로 채운다(§3-2).
- **읽히지 않는 화면 녹화를 통째로 넣기.** 로그·코드가 깨알같이 찍힌 클립은 정보가 아니라 소음이다. 보여 줄 조각만 레이어로 다시 만든다.
- **나레이션(TTS).** 이 장르는 무음 + 헤드라인이 기본. 소리는 배경음악·클릭음 정도.
- **30초.** 15~20초, 장면 5~6개.
- 헤드라인의 큰 slideUp, 직선 커서, 전부 가운데 정렬, 완전히 멈춘 구간.

## 1. 받아야 하는 것

1. **사용 흐름 3~4단계** — 이것이 곧 장면 구성이다. 예: 사진 올림 → 채팅창에 한 줄 → 만드는 중 → 완성본이 폰에서 재생.
2. **실제 화면** — 스크린샷이 있으면 조각으로 잘라 쓴다(모서리 둥근 PNG 로). 없으면 실제 제품의 메뉴 이름·버튼 글자·파일명을 물어 레이어로 그린다.
3. **마지막에 보여 줄 실제 결과물** — 폰 속에서 재생될 영상. 가짜면 광고 전체가 가짜로 보인다.
4. 브랜드 강조색 하나(없으면 로고에서), 헤드라인 문구(없으면 직접 쓴다 — 4개 이하, 각 두 줄 이내).

없는 것은 묻되, 한 번에 묻는다. 답을 기다리는 동안 장면표를 먼저 쓴다.

## 2. 장면표 (9:16 · 17.6초 기준, 16:9 는 헤드라인 왼쪽·패널 오른쪽)

| 구간 | 헤드라인 | 화면 | 다음 장면으로 넘어가는 법 |
|---|---|---|---|
| 0–1.3 | — | 로고 pop → 좌상단 워터마크로 줄어듦(scale 0.24, 위치 키프레임) | 로고가 빠지며 패널이 올라옴 |
| 1.3–4.0 | 재료는 이것뿐 | 제품의 실제 화면 패널(사이드바 아이콘·검색창·필터·썸네일·파일명). 재료가 하나씩 pop, 선택 테두리 | **패널 안의 작은 버튼으로 카메라 줌(1→2.8, 0.35초)**, 나머지는 밀려나며 fade |
| 4.0–4.9 | — | 버튼 하나만 크게. 커서가 곡선으로 들어와 클릭 | 버튼 눌림(0.93) 후 fade |
| 4.9–7.9 | 입력은 한 줄 | 입력창(첨부 썸네일 + 타이핑 + 전송 버튼). 커서 클릭 | 입력창 fade, 알약이 오른쪽에서 들어옴 |
| 7.9–10.7 | — | "만드는 중" 상태 + 결과물이 **자라는** 패널(트랙·노드가 하나씩 차오름, 재생 헤드가 등속으로 지나감) | 카메라가 위로 빠지고 폰이 아래에서 솟음 |
| 10.7–14.5 | 기다리면 완성 | 폰 속에서 실제 결과물 재생(0.95초 컷 4개) + 주변에 기능 칩(아이콘+글자)이 떠 있음 | 폰·칩이 같이 위로 빠짐 |
| 14.5–16.4 | 필요 없는 것 | 결과 카드 3~4장 `flipY` 스태거 | fade |
| 16.4–17.6 | — | 로고가 가운데로 돌아옴 + 한 줄 + 검정 CTA frame + 주소 | 마지막 300ms 정지 |

## 3. 문법 일곱 가지 (숫자는 9:16 1080×1920 px)

1. **카메라 한 대** — 보이지 않는 널(도형 `opacity 0`, 10×10)에 `scale`·`x`·`y` 키프레임. 그 장면의 조각 전부를 add 시 `attach_to {layer_id, position, scale, rotation}` 로 붙인다. 줌 중심 = 널의 중심이므로 **널을 다음 장면의 주인공 위에 둔다**. 이동량 = 목표 화면 좌표 − 널 좌표. 줌 이징 `cubic-bezier(0.7,0,0.2,1)`, 350ms. 부모의 부모까지 물려받으므로 칩에 붙인 아이콘도 카메라를 따라간다.
2. **UI 밀도** — 패널 하나에 디테일 15~30개, 40~45ms 스태거. 아이콘은 run_code 에서 24 그리드 선 아이콘 SVG 를 PNG 로 구워 올린다(stroke 2, round). 글자는 실제 메뉴명·파일명·용량. 나레이션 트랙은 파형 PNG `wipeRight 900 linear`, 자막 트랙은 실제 문구가 든 frame 블록, 컷 트랙은 실제 썸네일.
3. **화면 밖에 걸치기** — add 의 x·y 는 0~1 로 잘리고 width ≤ 1 이다. **박스는 화면 안에 두고 상수 키프레임 `x`/`y` 오프셋**으로 밀어낸다(`{timeMs:0, property:'x', value:-36}`).
4. **완전 정지 금지** — 머무는 동안 널이 2~3초에 30~70px 느리게 민다(linear). 로딩은 270° 호 path + `loop spin 1100` + 가운데 반짝이 `pulse`. 장면 내내 등속으로 가로지르는 것 하나(재생 헤드).
5. **헤드라인은 채워진다** — 같은 자리에 회색 `#9aa3af` 레이어(`slideUp` 10px · 320ms)와 먹색 레이어(`fade 380`, +170ms). 둘째 줄 +110ms. 굵기 800, 9:16 에서 92~100px.
6. **커서** — `x` 는 급감속 `cubic-bezier(0.16,1,0.3,1)`, `y` 는 `easeInOut` — 이징이 달라야 곡선이 된다. 화면 밖에서 들어와 도착 → 버튼 scale 1→0.93→1(`easeOutBack`) + 커서 0.84 딥 → `easeIn` 으로 화면 밖. 타이핑은 animator `unit:'char', durationMs:40, opacity:0`; **글자 수 × staggerMs 가 클릭 시각 전에 끝나는지 계산**(영문은 한글의 두 배 길이 — 75ms → 48ms).
7. **결과물은 자란다** — 트랙은 아이콘 pop → 라벨 → 내용 `wipeRight` → 체크 path `draw 300`. 마지막 트랙만 다른 색(앰버 `#ffb020`). 결과 카드는 `flipY 480` 130ms 스태거 + 상수→0 `x` 드리프트.

**색**: 종이 `#fcfcfd` · 먹 `#14181f` · 강조 한 색 · 선 `#e3e7ee` · 옅은 면 `#f1f4f8`. 그림자는 검정이 아니라 강조색 넓은 글로우(`shadowBlur 60, shadowOffsetY 14, α 0.22`).

## 4. 조립 순서

1. 장면표를 사용자에게 보여 주고 시작한다(승인을 기다리지 않는다).
2. **베이스 영상** — run_code 에서 종이색 캔버스를 만들고, 폰 장면이 있으면 베젤 PNG + 결과물 컷 4개를 둥근 마스크로 합쳐 `overlay` 의 y 식으로 솟아오르게 굽는다(`references/assets.md`). 업로드 → `create_edit_draft_from_clips`.
3. **클립이 끌고 온 자막을 지운다.** 결과물 클립에 자동 자막이 붙어 있으면 draft 의 자막 트랙으로 따라와 광고 위에 찍힌다(실측: "새 우 처럼 매 끈 해 져 요"). `get_edit_draft` 로 subtitles 를 확인하고 `delete_subtitle_entry` 로 비운다.
4. **빌더로 조립** — 레이어가 100개를 넘는다. 도구를 하나씩 부르지 말고 run_code 에 빌더를 저장해 돌린다(`references/builder.md`): px 좌표 도우미 → 널·부모 frame 먼저 → id 조회 → 자식. 배치는 20개씩.
5. **장면별로 본다** — `preview_motion_strip` 을 장면 하나(2~5초)씩, **6칸·cell 300 이하**로(더 크면 이미지가 빠진다). 의심 칸은 `preview_edit_frame` 한 장.
6. **두 번은 고친다.** 첫 조립은 반드시 어긋난다 — 좁은 글자 박스의 줄바꿈, frame 밑에 깔린 도형(z), 헤드라인을 덮는 확대 패널, 장면 사이 빈 프레임. 고치고 다시 본다.
7. 렌더 전에 스트립을 사용자에게 보여 준다. 렌더 → `check_video_status` → `create_share_link`.

`lint_motion` 은 이 장르에서 0점이 나온다(40ms 스태거를 동시 등장으로, frame 자식을 정지로 센다). 기준은 눈이다.

## 5. 함정

- 배치 add 의 `z_index` 는 지켜진다(2026-09 수정). 버튼·화살표·커서는 입력창 frame 보다 높게(60/61/99).
- 레이어 시간을 바꾼 뒤엔 `get_edit_draft` 로 확인한다. 가장 안전한 리타임은 삭제 후 재추가.
- 이미지 레이어엔 모서리 둥글기가 없다 → 둥근 PNG 를 미리 만든다. `borderRadius` 는 9:16 출력에서 약 1.78배로 커진다(사진 모서리 24px 에 맞춘 테두리는 18).
- frame 의 flow 자식 **이미지**는 작게 찌그러진다 → 투명 spacer 도형을 flow 자식으로 넣고, 아이콘은 절대 좌표로 같은 카메라에 붙인다.
- 폰 속 영상을 한 컷 3.8초로 두면 정지 화면처럼 보인다 — 0.95초 컷 4개.
- 확대한 패널이 헤드라인을 덮지 않게: 패널 왼쪽 끝 = 널x + 이동x + s·(패널x − 널x). 패널이 화면을 다 덮는 구간은 헤드라인을 잠깐 빼고 다른 문구로 다시 넣는다.
- 번역판은 `duplicate_draft` → 글자만 일괄 교체. 고정 폭 frame 안 글자는 넘치면 줄바꿈된다. **화면 속 결과물도 같은 언어로 다시 렌더**해야 거짓이 아니다.

## 6. 완료 조건

- [ ] 모든 장면 전환이 카메라·등퇴장으로 이어진다(플래시 없음)
- [ ] 회색 막대·색 점·빈 타일·캡슐 라벨이 없다
- [ ] 헤드라인 4개 이하, 전부 회색→먹 채움
- [ ] 커서가 곡선으로 들어와 누르고 나간다, 타이핑이 클릭 전에 끝난다
- [ ] 클립이 끌고 온 자막이 없다
- [ ] 장면별 스트립을 두 번 이상 보고 고쳤다
- [ ] 15~20초, 무음(또는 배경음악만)
