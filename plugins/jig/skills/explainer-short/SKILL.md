# 설명형 쇼츠

> 원칙 하나로 요약된다. **생성 이미지는 배경 플레이트만. 선·화살표·라벨·수치는 전부 레이어.**
> 2026-09-13 원포핸드 파일럿에서 그래픽까지 모델에게 그리게 했더니 한글이 깨지고 선이 뜬 다리로 갔고,
> 29회 생성 중 9회 반려, 고칠 방법은 재생성뿐이었다. 같은 영상을 레이어로 다시 만들면 생성 비용 0에
> 한글은 등록 폰트로 또렷하며 틀린 선은 점 좌표만 고친다(2026-09-14).

```
대본 → 실제 TTS 길이 → 장면표(ID) → 배경 사진(글자 0) → 레이어 그래픽(조립 문법) → 컷 → 검수 → 렌더
```

## 0. 먼저 정할 것 — 화면에서 무엇이 변하는가

주제마다 "보이게 만들 것"이 다르다. 이걸 안 정하고 시작하면 전부 슬라이드쇼가 된다.

| 주제 | 보이게 할 것 |
|---|---|
| 구조물·기계 | 하중 경로, 압력, 유체, 열 |
| 운동·자세 | 운동사슬(지면→말단), 관절 각도, 무게중심 이동, 도구 면의 각도 |
| 돈·경제 | 돈이 어디서 어디로, 시간에 따라 불어나는 양 |
| 몸·건강 | 물질이 지나가는 경로, 농도, 시간에 따른 변화 |
| 요리·공정 | 온도, 수분, 시간, 재료가 섞이는 순서 |

판정 기준 하나: **사진 한 장 위에 선과 화살표로 그려지는가.** 안 그려지면 이 포맷 소재가 아니다.
그 다음 네 문장을 확정하고 사용자 승인을 받는다 — 핵심 질문 / 핵심 메커니즘 / 보이는 것 / 차별점.

## 1. 대본

- 앞 3분의 1까지 문제·제약·모순을 키우고, 나머지에서 인과로 해소한다.
- 문장마다 원인·작용·결과가 하나씩 전진한다. 같은 말 반복 금지.
- **수치를 지어내지 않는다.** 확실한 것, 논쟁 중인 것, 설명을 위한 단순화를 구분해 말한다.
- 두 벌: ⓐ 시각 연출이 붙은 제작용 ⓑ TTS용 순수 텍스트. 한국어 기준 초당 7자 안팎(실측 285자=38.6초).

**게이트: 사용자 승인 전에 이미지 단계로 넘어가지 않는다.**

## 2. 실제 TTS 길이

`generate_tts` 를 **문장별로** 돌려 `duration_ms` 를 받는다. 그 숫자가 장면 길이다. 추정하지 않는다.
문장이 두 상태를 말하면 장면을 둘로 쪼개고 길이를 나눈다. 장면 사이 숨 0.2초.

## 3. 장면표와 ID

장면은 **상태가 바뀔 때** 만든다. 카메라 각도만 다른 건 장면이 아니다. ID 는 처음에 정하고 끝까지 안 바꾼다.
장면표에는 ID·길이·배경 사진 내용·**어떤 선/라벨/수치를 얹을지**·문장을 적는다.

## 4. 배경 사진 — 글자가 하나도 없는 사진

`generate_image` 9:16. 같은 인물이 여러 장에 나오면 첫 장을 `reference_image_urls` 로 걸어 인물·옷·장소·빛을 잇는다(실측: 연속성 완벽).

- 포토리얼. 실제 재질·광원·먼지·물기.
- 프롬프트 끝에 반드시: 글자·숫자·기호·화살표·지시선·차트·UI·HUD·자막·로고·워터마크·인포그래픽 **전부 금지**.
- **함정 — 모델은 "역동적인 스포츠 사진"을 만들려고 발을 땅에서 뗀다.** 접지·정지·특정 순간이 주제면
  "sole flat on the ground, not mid-air" 처럼 물리 조건을 CRITICAL 로 박는다. 발 뒤에서 찍으면 밑창이
  보이므로 옆에서 지면 높이로 찍게 한다(3회 만에 통과한 실측).
- 검수: 실제 그림을 본다. 지시한 순간인가, 접지·상태가 맞는가. 틀린 것만 다시 굽는다. 파일럿 반려율 6/16.

**배경은 정지 사진으로 충분하다.** 이미지 레이어에 `drift {end_scale 1.06}` 켄번스와 fade 0.25초면 영상처럼 읽힌다.
영상 생성(Veo/Kling)은 배경 자체가 움직여야만 할 때, 사용자가 비용을 승인했을 때만.

## 5. 그래픽 — 전부 레이어. 템플릿 먼저, 조립은 그 다음

**먼저 `list_mograph_templates` 를 본다.** 로어서드·콜아웃·숫자 카드·키네틱 타이틀·차트·브래킷·도장·화살표 연결·단계 번호·타임라인 등
20종은 디자이너가 등장·퇴장·타이밍을 넣어 둔 조각이라 `add_mograph_layer` 한 번이면 끝난다(문구·색·값만 바꾼다).
템플릿이 없는 것(사진 위 운동사슬 같은 자유 경로)만 아래 문법으로 손조립한다. 모션 일반 규칙은 `get_skill('motion-craft')`.

| 장면의 일 | 템플릿 |
|---|---|
| 코치 소개 | `lowerThird` (text 이름, subtext 직함) |
| 관절·부위 가리키기 | `callout` (anchorX/Y 는 박스 안 0~1 — 박스를 사진 위에 놓고 점을 찍는다) |
| 속도·각도 한 숫자 | `counterCard` (from/to/suffix) 또는 `progressRing` |
| 훅 문장 | `kineticTitle` (highlight 로 강조 단어) |
| 단계 제목 | `stepNumber` (같은 박스 위치 고정) · 절차 전체 `timeline` |
| 틀린 자세 판정 | `badgeStamp` |
| 초보/선수 비교 | `barChart` · `comparison` |

`list_motion_presets` 로 모션 카탈로그(이징·모션 경로·부모·매트·애니메이터·트림)를 본다. 배경 사진 위 좌표는 `preview_edit_frame` 으로 **실제 그림을 보고** 잡는다.
힘의 출발점은 힘이 실제로 생기는 곳이다(운동사슬은 **땅에 닿은 발**에서 시작).

레이어 박스를 풀캔버스(x0 y0 w1 h1)로 두면 사진 좌표(0~1)를 점으로 그대로 쓴다. 호·원처럼 `d` 를 쓰는 건 작은 박스에.

| 장치 | 도구 | 값 |
|---|---|---|
| 선·사슬·궤적 | `add_path_layer` | `points` 2~8개, `smooth:true`, `strokeWidth 8~11` |
| 앵커 → 선 → 화살촉 | `dots {at:'all'}` + `motion.enter {type:'draw', delayMs:250~350, durationMs:600~1600}` + `arrowEnd:true` | 화살촉은 선이 끝난 뒤 자동 |
| "속도가 붙는다" | `taper:'grow'` | 진행 방향으로 굵어짐 |
| 흐름이 움직인다 | `pulse {periodMs:1300~1500, lengthRatio:0.12, color:'#FFFFFF'}` | draw 끝난 뒤 자동 시작 |
| 비교선(회전 없음) | `dash:[16,12]`, `arrowStyle:'open'` | 점선도 draw 된다 |
| 회전·호 | `d:'M 8 62 A 42 22 0 0 1 92 46'`, `viewBox:'0 0 100 100'` | 골반 주변 작은 박스 |
| 지면반력 | 금색 굵은 화살표 + `glowColor/glowBlur 10` | 접지면에서 위로 |
| 라벨 | `add_text_layer` 작은 알약(shape 0.72 opacity)+텍스트, `motion.enter {type:'pop', durationMs:360, delayMs:선 완료 뒤}` | 장면당 1~3개, 짧게 |
| 핵심 수치 | `text.counter {from,to,durationMs,suffix}` | 장면당 0~1개, 폰트로 올라간다 |
| 배지·수치 강조 | `set_layer_motion` `loop {type:'breathe'|'pulse', delayMs:등장 길이}` | 정지 이미지처럼 안 보이게 |

색은 한 영상에 한 체계: **청록=몸을 타고 가는 힘, 주황=회전·틀린 길, 금=지면반력·이기는 궤적.**
거대한 타이틀·문장형 헤드라인 금지 — 설명은 나레이션이 한다. 주인공은 글자가 아니라 흐름이다.

타이밍(장면 안, ms): 배경 fade 0 → 앵커 점 0~250 → 선 250~1000 → 화살촉 → 라벨 pop 1100~1500 → 펄스 계속 → 퇴장 fade 180.
여러 선은 `delayMs` 를 늘려 읽는 순서대로 조립한다.

## 6. 검수 — 예쁜 것과 맞는 것은 다르다

1. `lint_motion` — 정지 레이어·퇴장 없음·동시 등장·죽은 구간·짧은 템플릿을 잡아 준다. error/warn 을 고친 뒤 점수 85 이상.
2. `preview_motion_strip from_ms/to_ms` — 장면 하나를 8칸으로 보고 조립 순서·리듬을 확인한다.
3. `preview_edit_frame(at_ms_list)` 로 장면마다 **선이 다 그려진 시각**과 **라벨이 뜬 시각**을 찍어 본다.
- 선의 시작·끝이 실제 위치인가(뜬 발이 아니라 닿은 발), 방향이 맞는가, 라벨이 사진의 얼굴·핵심을 가리지 않는가.
- 틀리면 `update_path_layer` 로 점만 고친다. 생성 비용 0.
- 한글은 폰트로 그려지므로 깨지지 않는다 — 깨져 보이면 그건 레이어가 아니라 배경 사진에 글자를 넣은 것이다.

## 7. 컷과 조립

나레이션 문장별 TTS 를 `add_audio_layer` 로 각 장면 시작에 올린다. 그래픽의 start/end 는 장면표 그대로.

- **베이스는 반드시 `blank-base`(검은 빈 클립).** 예전 생성 클립을 깔면 사진이 바뀌는 순간 클립 프레임이 비친다
  (실측: Veo 클립 끝프레임의 AI 그래픽이 매 장면 전환마다 튀어나왔다). 16초 × N 을 from-clips 로 잇고 마지막을 트림.
- **배경 전환은 겹침 크로스페이드.** 이전 사진에 퇴장 페이드를 주지 말고 다음 장면 시작 뒤 260ms 까지 남긴 채,
  다음 사진을 `enter fade 250ms` 로 위에 올린다(zIndex 는 장면 순서). 퇴장 페이드를 주면 그 순간 밑이 보인다.
- 자막은 최소로.

## 8. 마무리

- `failed=0` 은 완료가 아니다. 프리뷰를 눈으로 본 뒤 렌더한다. 렌더는 **사용자가 지시할 때만**.
- `create_share_link` 로 링크를 만들어 전달한다.

## 비용

배경 사진 장면당 1장(재생성 포함 평균 1.6장)이 전부다. 그래픽·라벨·모션은 0. 10장면 ≈ $2.
영상 생성이 붙는 순간 장면당 $0.5~1 이 더 들고 그래픽 품질은 오히려 떨어진다 — 기본값이 아니다.
